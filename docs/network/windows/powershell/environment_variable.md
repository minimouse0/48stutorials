# 环境变量

## 设置前必读

环境变量是Windows系统的关键配置之一。如果设置不当，**可能导致操作系统无法正常运行，甚至个人重要数据损坏丢失的后果**。为了防止对此教程造成误解导致损坏电脑，我不得不写一篇详细的教程硬控大家几分钟，为大家区分一个特别容易混淆的地方。

由于网站各类教程的简写，大多数人都有一个误区：新安装一个命令行工具，就需要“添加一个环境变量”。可是事实上，随便添加一个环境变量，并不能让这个命令行工具生效。我们要做的不是新建一个环境变量，而是修改已经存在的 Path 变量，往它的值里追加工具所在目录。

### 先搞清楚：环境变量和 Path 是什么关系

环境变量是操作系统维护的一组“名字 → 值”的配置。

```text
环境变量
├── Path
├── TEMP
├── USERPROFILE
├── JAVA_HOME
└── ...
```

`Path` 只是其中一个，但它很特殊：**操作系统会主动读它，用它来查找可执行文件**。

其他环境变量，比如 `JAVA_HOME`、`TEMP`，是给具体程序自己读的。你不装对应程序，或者程序不读它，它就没用。

所以：

- **环境变量**：大类。
- **Path**：大类里被系统特殊对待的那一个。

### 为什么“添加一个环境变量”不能让命令生效

假设你新装了一个工具，叫 `mytool.exe`，装在：

```text
D:\tools\mytool\mytool.exe
```

你在环境变量里新建一个：

```text
MYTOOL = D:\tools\mytool
```

然后打开命令行，输入：

```cmd
mytool
```

结果多半是：

```text
'mytool' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

为什么？  
因为系统根本不认识 `MYTOOL` 这个变量。它找命令时只看 `Path`，不看 `MYTOOL`。  
`MYTOOL` 这个变量只有“某个程序主动去读它”时才有意义。比如某个程序内部写了：  

```cpp
const char* dir = getenv("MYTOOL");
```

这时MYTOOL才会被读取，最终得到的结果是：*dir可以得到字符数组`"D:\tools\mytool"`。系统本身不会因为多了 `MYTOOL` 就去 `D:\tools\mytool` 找命令。

**随便加一个新环境变量，对“命令能不能直接运行”没有任何帮助。**

### 真正让命令生效的是什么

系统在命令行里找命令时，大致流程是：

1. 你输入 `mytool`。
2. 系统先看是不是内部命令。
3. 不是，就去 `Path` 里列出的目录，逐个找 `mytool.exe`、`mytool.cmd`、`mytool.bat` 等。
4. 找到就运行，找不到就报“不是内部或外部命令”。

所以你要做的是：**把 `mytool.exe` 所在目录，加进 `Path`。** ，也就是：

```text
Path = ...;D:\tools\mytool
```

这样系统才会去 `D:\tools\mytool` 找 `mytool.exe`。

> [!WARNING]
> 注意：加进 `Path` 的应该是**目录**，不是 exe 文件本身。

正确：

```text
D:\tools\mytool
```

错误：

```text
D:\tools\mytool\mytool.exe
```

很多人说“添加环境变量”，实际做的是：

1. 打开环境变量编辑窗口。
2. 找到 `Path`。
3. 点编辑。
4. 新增一行目录。

这本质上是**修改已有的 `Path` 变量**，不是“新建一个环境变量”。

严谨说法：

> 新装命令行工具后，通常只需要把它的安装目录追加到 `Path` 里。

而不是：

> 新装命令行工具后，需要给它添加一个环境变量。

后者容易让人误以为要新建 `MYTOOL=...` 这种东西。

### 那什么时候才需要“新建”一个环境变量

也有需要新建的时候，但目的不是让命令能被找到，而是让**某个程序能读到它需要的配置**。

常见例子：

#### 1. `JAVA_HOME`

装了 JDK 后，Maven、Gradle、Tomcat 需要知道 JDK 在哪。它们会去读 `JAVA_HOME`。

```text
JAVA_HOME = C:\Program Files\Java\jdk-17
```

注意：`java.exe` 能被直接运行，是因为 JDK 的 `bin` 目录在 `Path` 里；`JAVA_HOME` 是给别的工具读的。

#### 2. `ANDROID_HOME`

Android 构建工具需要知道 SDK 在哪。

```text
ANDROID_HOME = D:\Android\Sdk
```

#### 3. `HTTP_PROXY`

命令行工具下载依赖时走代理。

```text
HTTP_PROXY = http://127.0.0.1:7890
```

#### 4. `TEMP`

改临时文件目录。

```text
TEMP = D:\temp
```

这些变量的共同点：

- 它们不是为了让系统找到命令。
- 它们是给**特定程序**读的。
- 不装那个程序，或者程序不读它，设了也没用。

## 如何设置/修改

> [!WARNING]
> 再次提醒，安装新命令行工具时，必须**追加至Path变量**，添加新环境变量是错误的操作。

> [!DANGER]
> 千万不要直接设置整个Path变量的值，否则将导致系统无法正常工作！

通常情况下使用以下命令对整个环境变量进行暂时性的设置：
```
$env:变量名="变量的新值"
```

如果是永久设置，那么使用以下命令进行永久性的修改：
```powershell
[Environment]::SetEnvironmentVariable("变量名", "变量的新值", "如果为当前用户设置写User，为整个系统设置就是Machine");
```

### 如何追加

比如你要给一个命令行工具追加Path环境变量，那么使用以下命令：
```powershell
[Environment]::SetEnvironmentVariable("Path", $Env:Path + ";"+"可执行文件所在目录，不是可执行文件本身路径", "如果为当前用户设置写User，为整个系统设置就是Machine")
```
